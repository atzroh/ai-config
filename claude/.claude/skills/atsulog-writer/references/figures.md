# 図作成モードの詳細

記事に差し込む図を，Python（numpy + matplotlib）のスクリプトで生成する．
記事は後から自分で読み返す記録なので，図も「本文のどこを理解するための図か」がはっきりしているものにする．
ゴールは，ユーザーが**受け取ったものを記事に貼るだけで済む**状態である．図だけでなく，差し込む位置と差し込む文章まで用意する．

## 1. 手順

1. **記事を読んで候補を選ぶ．** 各 `##` / `###` の節ごとに，図があると理解が速くなる箇所を探す．1 節につき 1 枚（左右 2 パネルまで）を目安にする
2. **スクリプトを書く．** `assets/figure_template.py` をコピーして，図ごとに関数を 1 つ作る．すべての図を 1 本のスクリプトで生成できるようにする
3. **実行して画像を 1 枚ずつ目で確認する．** `view` で PNG を開き，4 節の「よくある問題」がないか見る．問題があれば直して再生成する．確認せずに渡さない
4. **差し込む位置を決め，差し込む文章を書く．** 5 節に従う
5. **スクリプトと PNG を渡す．** present_files で渡す（SVG も生成されるが，渡すのは PNG でよい）
6. **チャットで差し込み案を示す．** 図ごとに，差し込み位置と，そのまま貼れる Markdown ブロックを示す（形式は 5 節）

## 2. 図にする価値が高いもの

本文の数式・表・証明のステップに直接対応する図を優先する．装飾的な図は作らない．

- **数値の表**：表の値をプロットし，表の点を強調する（例：$(1+1/n)^n$ の表 → 対数軸のグラフ）
- **収束・極限**：数列や関数が極限値に近づく様子．極限値は破線で引く
- **不等式・はさみうち**：上界・下界と対象を同じ図に描く．証明で使った式をそのまま凡例にする
- **比較**：複数の方法・パラメータを並べる（例：$a = 2, e, 3$ の比較，収束の速さを対数軸の誤差で比較）
- **幾何的な解釈**：面積・接線・傾きなど，本文に「図形的には〜」と書いてある箇所
- **アルゴリズムの過程**：反復や近似の各段階を重ねて描く（例：オイラー法の $n = 1, 2, 4, 10$）

本文にない話題を図で補える場合（例：収束の速さの比較）は，その話題を導入文の中で 1〜2 文で補う．既存の本文は書き換えない．

## 3. 描き方の約束

- **記法は記事に合わせる．** 変数名，記号（$\log$ か $\ln$ か など），添字は記事の表記と同じにする
- **ラベルは英語と数式にする．** 日本語フォントがない環境でも文字化けしないため．記事の見出しが英語であることとも揃う
- **保存形式**：`figures/` 以下に PNG と SVG の両方を出力する．ファイル名は `01_compound_interest` のように「番号_内容」とし，番号は記事内の登場順にする
- **色**：主役は青，比較対象はオレンジ・緑，極限値や強調したい値は赤の破線に統一する（雛形の定数を使う）
- **タイトル**：その図で言いたいことを短く書く（例：`Compound interest converges to $e$`）
- **スクリプト冒頭の docstring** に，実行方法と必要なライブラリを書く．コメントは日本語でよい

## 4. よくある問題と対処

- **matplotlib の mathtext は LaTeX の一部しか使えない．** `\textstyle`，`\displaystyle`，`\dfrac`，`\operatorname` などはエラーになる．和は `1/0!+\cdots+1/n!` のように書き下すか，`\frac` を使う
- **浮動小数点の限界が図に出る．** 誤差を対数軸で描くと，約 $10^{-16}$ で頭打ちになり誤解を招く．限界に達する手前で打ち切る
- **凡例・注釈が線や塗りに重なる．** `loc` を変えるか，`set_ylim` で余白を作る．注釈が軸の外にはみ出していないかも確認する
- **線が多すぎて読めない．** 描画範囲を絞る（例：接線の図は $x \in [-1, 1]$ 程度），強調したい線だけ太くする
- **端の点のラベルが切れる．** `set_ylim` や `xytext` のオフセットで調整する

## 5. 差し込み位置と文章

### 差し込み位置の示し方

節名だけ（「Integral Form に入れるとよい」）では不十分．**どの行の前か後か**まで特定する．

- **目印の行を引用する．** 記事中の行の書き出し（10〜20 字程度）や数式をそのまま引用し，「〜の直後」「〜の直前」と書く．同じ書き出しが複数あるなら，一意に決まるまで引用を伸ばす
- **記事がファイルなら行番号も書く．** `grep -n` や `nl -ba` で確かめた行番号を添える（例：「42 行目『利息をつける回数を増やしても〜』の直前」）．チャットに貼られた記事は正確な行番号が分からないので，引用だけで示す．推測の行番号は書かない
- **置き場所の選び方**
  - 図は，それが説明している文・表・数式の直後に置く
  - 証明の途中（ステップの間）には置かない．命題の前（直感の図）か，証明の直後（$\blacksquare$ の後）に置く
  - 直感的な説明（「見方 1」など）の図は，その説明の段落の直後に置く
  - 表と同じ内容のグラフは表の直後，表を受けた地の文の前に置く

### 差し込む文章

各図について，次の形の Markdown ブロックを書く．

```markdown
<図を導入する 1〜2 文．何を描いた図で，どこを見てほしいか>

![<図の内容を表す短い日本語の説明>](figures/<ファイル名>.png)

<必要なら，図から読み取れることを 1〜2 文．前後の本文と重複するなら書かない>
```

- 文体・句読点は記事本文に合わせる（「である」調，「，」「．」）．SKILL.md の文体ルールがそのまま適用される
- 導入文は図の中身を具体的に書く（例：「下の図は，$n$ を対数軸にとって $\left(1+\frac{1}{n}\right)^n$ をプロットしたものである．」）．「以下に図を示す．」のような中身のない文にしない
- 左右 2 パネルの図は「左は〜，右は〜」と両方に触れる
- 図の英語ラベルが本文にない語（"upper bound" など）を使っているなら，導入文で日本語で対応を示す
- 差し込み後に前後の本文とつながるか確認する．直後の文が「この極限値が〜」のように図の前の文を受けているなら，図の位置をずらすか，後ろの文につながる書き方にする
- 画像パスは `figures/<ファイル名>.png` とし，ブログの画像置き場に合わせて書き換えるよう一言添える
- 既存の文章は書き換えない．図に合わせて本文を変えたほうがよい箇所があれば，差し込み案とは別に提案として書く

### チャットでの示し方

図ごとに次の形で書く．Markdown ブロックはコピーしやすいようにコードブロック（```` ```markdown ````）に入れる．

```
### 01_compound_interest
**位置**：Compound Interest の節，表の直後（「利息をつける回数を増やしても金額は〜」の段落の直前）
（Markdown ブロック）
```

図が多く（目安 5 枚以上）チャットが長くなる場合でも，差し込み案はチャットに書く．ユーザーが記事のファイルを渡していて，差し込み済みの版が欲しいと言った場合だけ，図のブロックを挿入した `.md` を別に作る．

## 6. 本文モードで図も頼まれた場合

「〜の説明を書いて．図も入れて」のように本文と図を同時に頼まれたら，本文の `.md` の中に 5 節の Markdown ブロックを最初から入れて書く．図に言及する文（「下の図のように〜」）も本文に自然に組み込み，図を前提にした説明にする（図で見せれば済む数値の羅列は減らしてよい）．図のスクリプトと PNG も同時に作って渡す．

## 7. 出力前のチェック

- すべての PNG を `view` で開いて確認したか
- 各図の差し込み位置が，引用（ファイルなら行番号も）で一意に決まるか
- 差し込んだ後，前後の本文と文のつながりが崩れないか
- 導入文が具体的か，記号・変数名・文体・句読点が記事と揃っているか
- スクリプトを一度で最後まで実行できるか（途中で直した場合は最初から再実行する）
