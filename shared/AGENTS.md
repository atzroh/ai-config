# Global Agent Instructions

## コミュニケーション
- 回答は日本語で、丁寧語 (です・ます) を使う。
- 結論を先に書き、その後に理由や仕組みを説明する。前置きや繰り返しは省き、簡潔にする。
- 考え方、処理の流れ、構成などの構造は ASCII アートの図で示す。単なる列挙はテキストで構わない。
- 絵文字は使わない。
- 要件が曖昧なときは、推測で進めずに質問する。

## 作業の進め方
- 最初に工程の全体像を示し、その後は変更を伴う工程 (ファイルの編集、変更を伴うコマンドの実行など) ごとに、返答を待ってから進める。ファイルの読み取りや調査は、確認なしで行ってよい。
- 変更は依頼された範囲に留める。
- リファクタは勝手に行わない。必要だと判断した場合は、理由を添えて提案する。
- 既存の書き方 (命名、構成、コメント) に合わせる。コメントは基本的に短くする。
- 次の操作は、実行前に必ず確認を取る。
  - ファイルの削除・上書き
  - git commit
  - git push、履歴の書き換え (rebase、reset --hard など)
  - sudo、パッケージの導入
- 完了を報告するときは、実行した検証 (コマンドとその結果) を書く。検証していないことは、未検証と明記する。

## コードとツール
- コード、コメント、コミットメッセージの言語は、各リポジトリの既存のものに合わせる。
- コミットメッセージは、Conventional Commits 形式 (`feat:`、`fix:` など) の 1 行にする。本文や `Co-Authored-By` などの行は付けない。
- Python: `uv` を使う (`uv run`、`uv add`)。システムの Python に `pip install` しない。
- Node.js: バージョンは `fnm` で管理する。パッケージマネージャーは、各プロジェクトの lockfile に合わせる。

## 環境
- OS: Kubuntu (Ubuntu 26.04 LTS)、シェル: zsh
- シェルでは以下のエイリアスが有効になっている。素のコマンドが必要なときは `command <cmd>` を使う。
  - `cat` -> `batcat --paging=never` (出力が装飾される)
  - `ls` / `tree` -> `eza`
  - `mv` -> `mv -i`、`cp` -> `cp -ir` (上書き時に確認待ちで止まる)
  - `fd` -> `fdfind`
